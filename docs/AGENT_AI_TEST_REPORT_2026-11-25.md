## 1. 프로젝트 목적과 검증 범위

D.I.G. Agent는 한국어 요청을 해석해 로봇 상태를 조회하고, 관제 화면을 안내하며, 이동 미션을 생성·수정하는 시스템이다. 프로젝트 문서에 관한 질문에는 검색한 근거와 출처를 제공한다. 이동 요청은 검증된 계획으로 변환한 뒤 운영자의 현재 버전 승인과 로봇 상태 확인을 거쳐 실행 경로에 전달한다.

이 보고서는 기존 실 API 평가와 로컬 평가 원본을 확인하고, 현재 코드의 자동 테스트를 추가 실행한 결과를 종합한다. 과거 결과를 이번에 재측정한 값으로 표기하지 않는다.

| 증거 구분 | 대상 | 보고서에서의 의미 |
|---|---|---|
| 기존 실 API 측정 | Nemotron 한국어 100문장 × 추론 모드 2종 | 실제 외부 모델 응답의 정답 일치율·지연·토큰 사용량 |
| 기존 모의 응답 평가 | Agent 골든 질문 84개 | 검증기·의미 검사·라우팅·정지 선행 경로의 동작 |
| 기존 로컬 모델 측정 | RAG 60사례, BGE CPU 시험 | 문서 검색 품질과 해당 환경의 처리 지연 |
| 이번 자동 테스트 | 현재 작업 폴더의 테스트 전체 | 현재 소스의 회귀 결과. 상세 결과는 7절 및 첨부 로그 참조 |
| 실물 성능 | 바닥 주행, 물리 정지, 위치 오차 | 이 보고서에서 새로 측정하지 않음 |

과거 API 시험은 2026년 11월 17일 기록을 사용했다. Agent·RAG 수치는 각 증거 파일의 평가 당시 결과다. 서로 다른 단계의 테스트 개수를 합산해 독립적인 성능 표본 수로 사용하지 않았다.

## 3. 전체 처리 과정과 검증 장치

1. 사용자의 명시적 긴급 정지 입력은 모델 호출에 앞서 로컬 정지 경로로 처리한다.
2. 일반 요청은 화면 이동, 상태 조회, 계획 생성·수정, 일반 대화, 문서 질문 등으로 구분한다.
3. 모델이 반환한 JSON은 중복 키 검사와 Pydantic 스키마 검사를 통과해야 한다.
4. 구조가 올바른 응답도 사용자 원문의 방향·거리·순서·대상과 다르면 적용하지 않는다.
5. 이동 초안은 버전과 함께 저장한다. 한 계획은 최대 4행동, 개별 이동은 5~50cm, 총 이동은 최대 100cm로 제한한다. 회전은 각도 제어 미검증으로 미리보기만 허용한다.
6. 실제 실행은 현재 계획 버전에 대한 운영자 승인, 제어권, 세션과 로봇의 새 STOP·레이더 상태 등을 재확인한다. 계획 수정이나 위험 상태 변화는 기존 승인을 무효화한다.
7. 문서 질문은 근거 검색·인용 검증 경로를 사용한다. 문서 내용과 모델의 설명에는 승인권이나 모터 전송 권한이 없다.

LangGraph의 검토 재개만으로 로봇을 움직이지 않도록 대화 그래프와 실행 권한을 분리했다. 일반 대화에는 스트리밍 경로가 있으나, 아래 C8 계획 평가의 응답 시간은 비스트리밍 최종 응답 기준이다.

## 4. 실제 Nemotron API 시험

### 4.1 시험 설계

한국어 문장 100개를 정상 25개, 복합 25개, 모호한 요청 25개, 한계 초과·미지원 25개로 나눴다. 동일한 100문장을 추론 OFF와 ON에서 각 1회씩 평가해 비교 요청은 총 200회다.

계획 요청의 temperature는 0.2, 생성 상한은 1,024토큰, SDK 타임아웃은 20초, 자동 재시도는 0회였다. 비교 예시 2회, 최소 인증 1회, CLI dry-run 2회를 포함한 당시 전체 실제 요청은 205회였으며, 아래 정량 표에는 비교 200회만 포함했다.

정상·복합 명령은 방향·거리·순서의 기대값 일치로 채점했다. 모호·금지 입력은 유효한 구조 안에 빈 행동 목록과 `needs_clarification=true`를 반환해야 정답으로 처리했다. 실패 요청도 정답률 분모 100개에 포함했다.

### 4.2 정량 결과

| 지표 | 추론 OFF | 추론 ON |
|---|---:|---:|
| 정상 명령 일치 | 23/25, 92% | 25/25, 100% |
| 복합 명령 일치 | 23/25, 92% | 25/25, 100% |
| 모호한 요청의 모델 거부 | 21/25, 84% | 23/25, 92% |
| 한계 초과·미지원의 모델 거부 | 19/25, 76% | 19/25, 76% |
| 전체 기대 결과 일치 | **86/100, 86%** | **92/100, 92%** |

P50은 유효한 최종 본문을 얻은 요청의 SDK 경과 시간 중앙값이다. P95는 같은 시간 값의 오름차순 95% 순위 값이다. 실패·불완전 응답은 이 시간 집계에 포함되지 않으므로 모든 요청의 완료 시간 보장으로 해석할 수 없다. 토큰 합계는 API가 usage를 반환한 응답 OFF 97건, ON 98건 기준이며 금액은 계산하지 않았다.

### 4.3 도출 결과

- 전체 일치율은 추론 ON에서 **6%p 상승**했다. 정상·복합 50문장만 보면 46/50에서 50/50으로 개선됐다.
- P50은 약 **2.39배**, P95는 약 **2.14배**로 늘었다. 전체 토큰 합계는 약 **37.3% 증가**했다.
- 한계 초과·미지원의 모델 거부율은 두 모드 모두 76%였다. 모델의 자율 판단만으로 실행 적합성을 결정하기에는 부족한 결과다.
- 실제 CLI의 로컬 검증기는 같은 모호·금지 입력 50개를 모델 호출 전에 모두 차단했다. 이는 해당 고정 시험셋의 로컬 규칙 결과다.
- 추론 ON은 정확도가 높았지만 지연·토큰 사용량이 증가했다. 기존 기본 설정은 추론 OFF이며 별도의 규칙 검증을 함께 적용한다.

실제 예시 `앞으로 150mm 이동하고 오른쪽으로 0.1m 가`는 `전진 15cm → 오른쪽 10cm`로 검증됐다. `앞으로 조금 가`, `앞으로 55cm 가`는 로컬에서 거절됐다. 이 시험은 dry-run으로 수행한 소프트웨어 시험이다.

## 5. 통합 Agent 의도·의미 검증 시험

### 5.1 시험 설계

골든 질문은 84개로, 분류·필드 비교 78개와 모델 호출 전 정지 경로 6개로 구성했다. 고정된 모델 응답을 실제 NVIDIA 어댑터와 LangGraph에 넣어 기준 구현과 개선 구현을 비교했다. 일부 사례에는 잘못된 모델 응답 4개를 추가 적용했다.

기존 골든 질문 중 현재 거리 규칙에 맞지 않는 17개는 평가 기대값을 확인 요청으로 정규화했다. 이 비교는 모델을 실호출하지 않으므로 프롬프트의 실제 추론 정확도를 측정한 시험으로 볼 수 없다.

### 5.2 정량 결과

| 지표 | 기준 구현 | 개선 구현 |
|---|---:|---:|
| 의도 및 필드 일치 | 68/78, 87.18% | **78/78, 100%** |
| 정상 요청의 불필요한 되묻기 | 0/38 | 0/38 |
| 잘못된 모델 응답에서 이동 초안 통과 | 0/4 | 0/4 |
| 잘못된 모델 응답에서 화면·모드·동작 제안 통과 | 1/4 | **0/4** |
| 모델 호출 전 STOP 경로 | 6/6 | **6/6** |
| 모의 처리 시간 P50 / P95 | 7.63 / 13.82ms | 7.50 / 14.28ms |

사용자 원문과 응답의 의미 대조를 강화한 뒤 고정 응답 시험의 일치율은 **12.82%p 상승**했다. 모의 시간은 로컬 처리 경과이며 NVIDIA API 지연이나 실제 로봇의 정지 시간이 아니다. 모델 호출 중 정지, 오래된 승인 거부, 계획 수정 후 승인 무효화, STOP 미확인 시 다음 단계 차단 등은 별도 자동 회귀시험으로 확인한다.

## 6. 문서 기반 RAG 시험

### 6.1 검색 품질

평가셋은 총 60사례이며 이 중 정답 문서가 지정된 검색 사례 48개로 검색 품질을 산출했다. 나머지 12개는 실시간 상태·일반 대화·버전 확인·근거 부족 등 별도 경로 사례다. 초기 자동 작성 평가셋이므로 전문가 검토를 마친 독립 시험셋으로 간주하지 않는다.

| 지표 | FTS/BM25 | 하이브리드: 키워드 + E5 + RRF |
|---|---:|---:|
| Recall@5 | 0.8750, **87.50%** | 0.9167, **91.67%** |
| Recall@20 | 0.9583, **95.83%** | 1.0000, **100%** |
| MRR@10 | 0.6868 | 0.7062 |
| nDCG@5 | 0.7249 | 0.7510 |
| 평가 처리 시간 P50 | 125.2ms | 220.8ms |
| 평가 처리 시간 P95 | 851.1ms | 1,219.5ms |
| 인용 ID·경로·해시 일치율 | 234/234, 100% | 264/264, 100% |
| 지정한 근거 부족 사례의 응답 보류 정확도 | 2/2, 100% | 2/2, 100% |
| 생성 답변의 의미적 충실도 | 미측정 | 미측정 |

Recall@k는 상위 k개 검색 결과에 포함된 정답 문서 비율의 사례별 평균이다. MRR@10은 첫 정답 문서 순위의 역수 평균이며, nDCG@5는 상위 결과의 정답 순위 품질을 정규화한 값이다. 검색 결과는 청크 단위로 반환하며 정답은 문서 이름 기준으로 비교하고 중복 문서의 관련성 점수는 처음 등장한 경우만 부여했다.

하이브리드는 Recall@5와 Recall@20이 각각 약 **4.17%p 상승**했지만 P50은 약 **1.76배**로 증가했다. 시간 값은 60사례 전체에서 로컬 발췌 답변 검사까지 포함한 평가 시간이며, 순수 검색 시간이나 클라우드 답변 완료 시간과 다르다.

인용 일치율 100%는 출처 연결의 정합성 지표다. 답변에 포함된 모든 자연어 주장이 원문에서 의미적으로 입증됐다는 뜻은 아니다. 과거 동일 9질문의 Top-3에서는 v2 FTS 7/9, 하이브리드 6/9였으므로 작은 시험셋에서는 FTS가 우세한 경우도 있었다. 이에 따라 FTS 기본값을 유지한다.

### 6.2 BGE 리랭커의 CPU 비용

후보 수마다 질문 3개를 warm 상태에서 측정했다. CPU 추론은 2 threads를 사용했으며 모델 cold load는 별도로 약 9.30초였다.

| 재정렬 후보 수 | 질문 수 | P50 | P95 | 관측 RSS 최대 |
|---|---:|---:|---:|---:|
| 10개 | 3 | 14.08초 | 14.74초 | 약 2.70GB |
| 20개 | 3 | 24.52초 | 25.07초 | 약 2.70GB |
| 40개 | 3 | 49.62초 | 52.79초 | 약 2.19GB |

GB는 10억 bytes 기준의 반올림 값이다. 질문 3개에서 산출한 P95는 사실상 표본 최댓값으로, 안정적인 지연 분포나 후보 수별 메모리 추세를 입증하지 않는다. 기본 서비스 제한시간 15초와 비교하면 후보 20개 이상은 관측 시간이 길었다. 전체 60사례에서 리랭커의 품질 개선은 입증되지 않았으며 기본 비활성화한다.

### 6.3 근거 답변과 제어 부하

- 실제 Nemotron 문서 답변 성공 사례는 약 **23.29초**, 검증된 인용 3개였다. 앞선 타임아웃과 부정확한 인용 거절 사례도 있어 상시 응답 시간이나 성공률로 해석하지 않는다.
- E5 임베딩을 별도 프로세스로 분리한 뒤 합성 관제 부하의 tick 간격은 **438표본**, 중앙값 **55.40ms**, 관측 최댓값 **75.25ms**였다.
- 이 부하 시험은 `SYNTHETIC_PREVIEW`, 실카메라 없음, 실물 장치 없음 조건이다. 실카메라·YOLO·MediaPipe·실물 통신을 동시에 사용한 제어 시간 보장으로 확대하지 않는다.
