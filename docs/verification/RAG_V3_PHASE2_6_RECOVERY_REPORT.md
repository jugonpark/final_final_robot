## 3. 검색 및 근거 완결성

기존 실험의 8개 문서에 방향 관계가 있는 `CENTRAL_CONTROL_WORKFLOW.md`를 더한 **9개 고정 리비전 문서**를 모든 비교군에 동일하게 넣었다. 이전 실제 실험의 8개 문서 결과와 같은 실험이라고 혼합하지 않는다. 원문 SHA와 리비전은 [검색 비교 JSON](rag_v3_phase2_6/retrieval_comparison.json)에 있다.

| 질문 | FTS | 단순 중복 제거 | 구조 검색 | 구조+다양성 |
|---|---|---|---|---|
| 061 통신 | 표지 누락 | 표지 누락 | 포함 | 포함 |
| 062 Qt 기술 | 표지 누락 | 표지 누락 | 포함 | 포함 |
| 063 UNKNOWN | 표지 누락 | 표지 누락 | 포함 | 포함 |
| 다른 표현 4개 | 4/4 포함 | 4/4 포함 | 4/4 포함 | 4/4 포함 |

합계는 FTS 4/7, 단순 중복 제거 4/7, 구조 검색 7/7, 구조+다양성 7/7이다. 판정은 평가 전용 핵심 표지의 **입력 포함 여부**다. 정답의 함의·충분성·최종 답변 성공률이 아니다. 추론에는 표지나 Gold를 전달하지 않는다. 061은 UDP 표지 외에 명령/텔레메트리 및 방향 관계 원문도 별도 확인했다. 최종 후보에는 `ESP32 명령 UDP 8888`과 `PC 텔레메트리 UDP 8889`를 잇는 이전 구조 도식이 들어 있으며, 과거 범위를 지우는 생성 주장은 별도로 차단한다.

격리 실행에서 Dense 모델은 구성하지 않았다. `hybrid_unavailable` 비교군은 기존 Hybrid의 FTS fallback이며 **실제 Dense/리랭커 비교가 아니다**. 모델을 자동 설치하거나 외부에서 받지 않았다.

표는 제목을 별도 heading으로 전달하고 헤더·구분선·해당 행을 함께 보존한다. 값만 추출해 단위·열의 적용 버전을 없애지 않는다. 분량이 넘는 일반 문장은 완전한 문장만 후보로 만든다. legacy 잘린 청크는 정확한 원문을 확보하지 못하면 사용하지 않는다.

통신 방향이 Mermaid에만 명시된 자료도 있어 후보에서 제한된 선언적 도식 문법을 추가했다. `flowchart/graph` 방향과 단순 node→node 간선만 허용하며 원문 그대로 전달한다. Python 등 실행 코드, link/click/style 지시문과 신뢰할 수 없는 명령 패턴은 제외한다. 이는 코드를 실행하거나 누락된 관계를 추론해 만드는 기능이 아니다.

원문은 DB SHA와 일치하는 로컬 바이트 또는 고정 Git 리비전에서만 복원한다. 동일 문서·리비전·프로파일·trust를 넘는 인접 문맥 결합은 없다. 초기 문서별 Git 4초 제한이 검색 불안정을 만들었다. 초기 산출물은 [initial8](rag_v3_phase2_6/retrieval_comparison_initial8.json)에 별도로 보존했고, 최종 비교는 단일 Git archive로 준비한 검증된 snapshot과 해시 검사로 수행했다. 초기 실행과 최종 실행을 성능 전후 측정으로 비교하지 않는다.

`CENTRAL_CONTROL_WORKFLOW.md`에는 이전 구조와 향후 계획이 함께 있다. 이를 현재 소유권/승인 정책의 증명으로 사용하면 안 된다. 목표 구조/향후 계획 절의 단정은 후보에서 추가 차단하며, 통신 방향도 문서 기준으로 한정한다.

## 4. Evidence ID와 출처 계약

- ID는 서버에서 요청마다 임의 토큰+E 번호로 만든다. 모델에게 원문·절·버전·상태와 ID만 제공한다.
- 다른 요청의 ID, 존재하지 않는 ID, 추가 필드와 잘못된 스키마는 거절한다. 유사 근거로 자동 교체하지 않는다.
- 선택 시와 의미 검증 후 활성 chunk, 문서 상태, SHA, source digest, 리비전, trust, 프로파일과 정확한 원문을 재확인한다.
- 내부 unit ID와 실제 DB chunk ID를 구분한다. 최종 출처 열람용 `id`는 원래 DB ID이며, 발췌와 관련 claim 연결을 유지한다. 후보 배열 인덱스는 영속 문서 번호로 해석하지 않는다.
- API의 dynamic enum/structured output 지원은 이번에 조회하지 않았다. 기존 JSON 텍스트 응답을 서버에서 엄격히 검사하는 계약만 구현했다.

## 5. 생성·관련성·완전성·복구

생성 프롬프트는 핵심 결론 우선, 단일 주요 사실, 필요한 근거 ID, 조건·수치·버전 보존, 무관한 파일/설치/영상 구조 제외를 요구한다. 모델의 core/detail 표시는 답변 관련성 증명으로 쓰지 않는다.

독립 관련성 검사는 통신 질문에서 카메라/프레임/GUI 타이머 설명만 남는 사례를 차단한다. 기술 질문에는 구현 기술 관계, UNKNOWN 질문에는 상태/유효성/수신 의미를 요구한다. 복수 의도 중 빠진 범위 및 하드웨어 비교 범위도 별도 표시한다. 생성기가 보고한 미확인 사항은 사실로 출력하지 않고 부분 답변 여부에만 사용한다.

이는 **필요조건 휴리스틱**이며 질문의 모든 필수 사실을 파악하는 보정된 semantic completeness 판정은 아니다. 한국어 연결어와 복수 문장으로 명확히 드러나는 복합 주장을 거절하지만, 모든 숨은 복합 사실을 파싱하지는 못한다. 남은 주장의 전체 함의는 semantic judge가 검증해야 한다. core20 Gold는 실서비스 추론에 사용하지 않는다.

복구는 단일 bounded 구조 검색/근거 재선정으로 제한했다. 잘못된 ID나 문장을 서버가 고쳐 통과시키지 않는다. 자동 모델 재생성은 0회다. 추가 복구를 적용하려면 새 후보도 모든 검증 단계를 거쳐야 하고 별도 예산이 필요하다.

## 6. 규칙 개선과 반례

`목표 손 제스처`, 목표 위치/속도와 설계·성능 목표를 구분하는 후보를 통합했다. 동일 주어·무주어 절·다만/해당 등 암시적 연결 조건은 유지한다. 다른 부품의 미검증 상태를 무조건 현재 주장의 조건으로 적용하지 않는다.

한국어 `아닙니다/아닌/아님/아닐`, 미지원·제외·사용하지 않음도 검토한다. 수치 후보는 명시적 단일 전압 문법에서 대상/값/단위가 일치하는 경우만 기존의 과잉 차단을 줄인다. 뒤바뀐 값, A/V 혼동, 같은 대상의 충돌 값, 관련 조건·부정과 CAD/설계 상태는 계속 차단한다. ESP32 5V/모터 12V는 **합성 테스트 문장이지 로봇 사양이 아니다**.

Phase 2.5의 전역 regex mock patch 대신 후보 전용 규칙을 사용한다. 운영 verifier의 전역 상태를 바꾸지 않아 동시 요청과 기준선에 영향을 주지 않는다. 안전성 과장·실시간 추측·버전 혼합·부품/숫자/단위/원문 복사 검사와 의미 검증을 제거하지 않았다.

## 8. core20 활용

기존 20문항·53개 사실·리비전·hash·human_review_pending 상태를 그대로 유지했다. [provisional retrieval](rag_v3_phase2_6/core20_provisional_retrieval.json)에는 각 사실의 출처가 9개 corpus에 있는지, 정확한 발췌가 입력에 있는지 따로 기록했다.

48/53개 사실의 출처가 corpus 안에 있고, 최종 후보에서는 39/53개의 정확한 발췌가 선택됐다. 출처가 corpus 안에 있으나 정확 발췌가 선택되지 않은 것은 9개, corpus 밖 출처는 5개다. 이 수치는 **답변 Coverage가 아니며**, 동등한 다른 근거로 표현된 사실을 놓칠 수도 있다. live/근거 부족 질문에는 positive fact 분모가 없을 수 있다. 사람 검토 완료나 깨끗한 holdout이라고 표시하지 않았다.

## 9. 지연 계측과 SDK 후보

`Timings`는 검색, 구조적 근거 선택+ID 구성, 생성 wrapper, 결정론적 검사, 의미 검증 wrapper, 조립, 전체 응답을 각각 기록한다. SDK 후보는 초기화, 요청 데이터 구성, SDK create, 파싱, 종료와 호출별 내역을 기록한다. SDK create는 네트워크·서버·클라이언트 작업을 포함하며 순수 서버 추론 시간이 아니다. SDK 세부값은 같은 Timings를 주입해 수집할 수 있다.

SDK 재사용은 한 객체의 설정 snapshot에 한정한다. 설정을 바꾸려면 새 객체를 만들어야 한다. 전체 생성+검증 요청을 lock으로 직렬화하여 shared deadline/호출 수가 섞이지 않게 한다. 동시성 처리량 최적화는 하지 않았다. 최대 2회, 재시도 0회이며, 전송 전 durable 예산 예약 callback이 없으면 구성할 수 없다. 오류가 난 client는 폐기하고 자동 재시도하지 않는다. 종료는 호출자가 명시적으로 수행하고 시간도 따로 기록한다.

현재 실제 API 호출이 없으므로 새 초기화/create/파싱/종료의 **실 API 시간은 미측정**이다. Mock과 로컬 검색 시간은 실제 응답 지연 개선으로 해석하지 않는다. 과거 P50 25.76초는 그대로이며 과거 미계측 단계는 소급 추정하지 않는다.

| 검색 | 10.73 / 882.78 / 208.00 | 미측정 |

기존 세부값은 [Phase 2.5 원기록](rag_v3_phase2_5/latency_decomposition.json)이 기준이다. 소수점 이하를 생략한 SDK 항목은 반올림 표시이며 새 측정값이 아니다. [Mock 계측 표본](rag_v3_phase2_6/mock_timing_sample.json)은 별도 합성 응답 경로에서 단계 계측·두 호출/한 초기화·명시 종료가 연결되는지를 검사한다. Mock 시간의 비율로 실제 API 개선율을 계산하지 않는다.

Mock 표본은 검색 428.00ms, 근거 선택 14.83ms, 요청 구성 0.154ms, 생성 wrapper 0.575ms, 결정론적 검사 63.71ms, 의미 검증 wrapper 0.215ms, 조립 0.249ms, 전체 530.27ms였다. fake client의 초기화 0.008ms/create 합계 0.375ms/파싱 0.082ms/종료 0.006ms는 **실제 OpenAI SDK나 서버 측정이 아니다**. 초기화 1회·예약/호출 2회·종료 1회를 확인했다. wrapper 안에 SDK 세부 구간이 중첩되므로 이 수치들을 모두 합쳐 전체 시간으로 계산하면 안 된다. 명시적 공유 client 종료는 응답 반환 후 별도 계측이다.

## 10. 안전·개인정보·최종 검사

기존 cloud=0 및 사용자 문서 외부 전송 제한은 그대로다. 후보는 검색 확장 과정에서 검사한 전체 범위에 대해 기존 cloud_allowed를 적용하여, 그 안에 user/local reference가 있으면 모델 호출을 보류한다. 보수적 범위 때문에 무관한 비공개 문서가 있어도 보류가 늘 수 있으며, 이를 분리 전송으로 우회하지 않았다.

현재 상태 질문과 모호한 하드웨어는 문서로 사실 확정하지 않는다. 최종 답변 전 출처 재확인을 유지한다. RobotSession·UDP·모터·엔코더·역기구학·레이더·Emergency STOP·미션 승인·Control Lease·하드웨어 프로파일·접근 정책 파일은 수정하지 않았다. 실행 관제 재시작과 실물 구동도 없다.

최종 통합 검사는 **59 passed, 44 subtests passed (276.71초)**다. [실행 로그](rag_v3_phase2_6/validation.log). 신규 후보 17개 검사와 기존 RAG v3/Phase 2/2.5 검사, Agent의 STOP 선점·늦은 RAG 폐기·승인 우회 차단 3개 회귀 검사를 포함한다. 통과 숫자는 모델 품질 정확도가 아니다. 기존 전체 364개 회귀 테스트를 이번에 재실행했다고 주장하지 않는다.

[보존 검사](rag_v3_phase2_6/preservation_check.json)는 시작 시 기록한 기존 424개 파일의 hash가 모두 일치하고 변경 파일이 0개임을 확인했다. 기존 장부는 12/12, 새 외부 요청은 0회다. [후보 manifest](rag_v3_phase2_6/candidate_manifest.json)에 새 코드·프롬프트 포함 파일과 보고서 hash를 고정했다. `git diff --check`도 통과했다. 기존 Qt 파일의 LF→CRLF 경고는 있었으며 해당 파일 바이트는 변경하지 않았다.

## 11. 추가 실제 API 계획과 운영 판단

기존 **12/12 장부 보존**, 이번 새 장부 생성·승인·외부 API 요청 **0회**다. 평가 스크립트에는 live 옵션이 없고 네트워크를 차단한다.

후속 [별도 승인안](rag_v3_phase2_6/proposed_api_plan.json)은 061/062/063 각각 생성 1회+의미 검증 최대 1회, 총 **최대 6회**다. 실패·재시도·metadata·기타 요청도 같은 상한에 포함하고 자동 재생성은 강제하지 않는다. 이 JSON은 승인이나 예산 장부가 아니다. 새 예산은 승인 후에만 만든다. 원래 장부 초기화나 우회는 하지 않는다.

실험 전 고정 후보 코드/프롬프트/근거 hash, 독립 Gold 검토, 공개 문서와 질문의 전송 허용, actual input의 조건·버전 보존, 요청별 단계 계측과 실패 기록을 확인해야 한다. dynamic enum 확인에 별도 호출이 필요하면 그 호출도 예산에 포함하거나 추가 승인을 받아야 한다. 로컬 core20 검토와 새로운 holdout 검증도 필요하다.

**운영 기본값 적용 및 Phase 3 진입은 보류**한다. 검색 입력 복구와 로컬 경계 검사는 완료할 수 있지만 실제 모델의 직접성·원자성·자연스러움·의미 판정·지연 개선은 아직 검증하지 못했다. 특히 관련성 휴리스틱의 누락/오탐, corpus 밖 근거, 복합 사실 탐지 한계, 보수적 privacy 범위와 직렬 SDK 처리량은 남은 위험이다.
