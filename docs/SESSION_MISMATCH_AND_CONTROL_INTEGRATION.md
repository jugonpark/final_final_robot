# D.I.G. 세션 전환과 손동작·자연어 제어

2026-11-17 분석 및 소프트웨어 검증. ESP32 펌웨어 업로드와 실물 모터 구동은 수행하지 않았다.

## SESSION_MISMATCH의 발생 지점

- 자연어 실행 로그 `logs/llm/580604cef29c4337b546dec32de5624b.jsonl`에서 19:18:46.353 KST에 새 세션 `3082409957`의 STOP `seq=1`을 보냈다. 약 118ms 뒤 `SESSION_MISMATCH`로 중단했고 같은 세션으로 STOP을 다시 시도했다. 새 세션의 정지 확인 기록과 `cmd_move` 송신 기록은 없었다.
- 이전 수동 시험 로그 `logs/20261117_185320_870550/events.jsonl`에는 세션 `2836662309`, 부팅 ID `3557285028`, 마지막 PC STOP `seq=2826`, 마지막 일치 수신 `last_seq=2823`가 남았다. 실패한 자연어 실행의 거절 패킷에는 수신 세션·부팅 ID가 기록되지 않았다. 실패 패킷이 이 수동 세션인지, 재부팅이나 다른 송신기의 패킷인지는 확인할 수 없다.
- 코드에서 확인한 직접 원인은 새 세션의 STOP에 대한 첫 정지 응답을 기다리는 중에도 세션이 다른 정상 형식의 응답을 즉시 실패로 처리했다는 점이다. ESP32는 약 200ms 주기로 텔레메트리를 보낸다. 기존 클라이언트 종료의 마지막 STOP에는 수신 확인 절차가 없었다. 기존 응답이 전환 직전에 생성된 경우 새 소켓에 도착할 수 있다. 같은 초기 패킷 순서를 모의 ESP32로 재현했다.

참조 펌웨어는 현재 움직이면 새 세션의 첫 명령에서 즉시 정지하고, 정지 상태에서는 새 세션을 받을 수 있다. STOP과 heartbeat가 handshake를 갱신한다. PC 모드 사이의 소유권은 대시보드와 수신 포트가 관리한다. 다른 LAN 호스트를 인증하거나 독점권을 부여하는 보드 기능은 현재 없다.

## 수정한 전환 규칙

| 상황 | 동작 |
| --- | --- |
| 모터 시험 또는 손동작 추종 연결 해제 | 구동 권한을 지우고 STOP을 보낸다. 약 850ms 동안 새 STOP에 대한 응답을 확인한 뒤 송신 스레드와 소켓을 종료한다. 확인 실패 시 화면과 로그에 남긴다. |
| 신규 모드 연결 | 이전 모드가 소켓을 닫고 STOP을 확인한 경우에만 새 구동 경로로 넘어간다. 이전 STOP이 미확인이면 같은 ESP32에서 모터 시험의 통신 전용 연결을 명시적으로 다시 한다. |
| 새 STOP 확인 전 이전 세션 응답 | 같은 ESP32가 정상 정지를 보고하는 초기 짧은 구간에서만 보류하고 로그에 기록한다. 넘겨받은 세션 정보가 있으면 이전 부팅 ID·세션·최종 송신 순번 범위를 검사한다. 이 응답으로 실행을 승인하지 않는다. |
| 실행 중 세션 변경·재부팅·다른 세션의 목표 도달 | 구동 권한을 폐기하고 STOP을 시도한다. 새 이동이나 자동 재출발을 금지한다. LLM 중단은 제한 시간 동안 정지 응답을 별도로 확인한다. |
| 동시 연결 또는 GUI 종료 | 대시보드의 실물 모드는 한 번에 하나다. 외부 PC 프로세스와는 UDP 8889 배타 바인드를 사용한다. 긴급 정지는 활성 제어기에 전달된다. GUI 종료 시에도 해당 제어기가 STOP을 처리한 뒤 종료한다. |

로그의 `SESSION_DIAGNOSTIC`, `CONTROL_RELEASE`, `STOP_CONFIRMED`, `ABORT_STOP_RESULT`에는 시각과 제어 모드·소유자, 송수신 세션 및 순번, boot ID, 상태, fault, STOP 송신·확인 여부를 남긴다. 새 불일치가 발생하면 대시보드에서 송·수신 세션을 비교할 수 있다. 과거 실패 로그에 없던 수신 ID를 소급해서 확정할 수는 없다.

## 사람 추종이 끊긴 원인과 조정 방법

`logs/20261117_191712_623519/events.jsonl`에서 처음 분석한 상태 4,915건 중 4,825건은 사람 한 명이 검출됐다. 정지 사유의 주된 항목은 `CAMERA_FAILED_OR_STALE` 2,163건이었고, 사람 박스 크기 제한도 132건이었다. 중복 상태 기록을 제거한 3,363개 추론 결과의 처리시간은 P50 160.3ms, P95 263.8ms였다. 시점별 영상 나이는 250ms 이내가 2,752/4,915, 500ms 이내가 4,781/4,915였다. 이는 저장 기록에 대한 분석이며 새 설정으로 재측정한 실물 성능은 아니다.

제스처 연속성을 검사할 때 현재 처리 시각과 이전 캡처 시각을 비교해 추론 지연이 제스처 간격으로 포함되는 문제도 수정했다. 연속성은 두 캡처 시각의 차이로 계산하고, 현재 프레임의 유효시간은 따로 검사한다.

**손동작 추종** 탭에서 시뮬레이션 상태로 설정을 바꿀 수 있다. 영상 유효시간은 250–500ms, 제스처 유지시간은 0.3–1.5초, 최소 프레임은 2–8개, 사람 박스 최대 높이는 화면의 85–98% 범위다. YOLO 추론 해상도도 설정할 수 있다. **느린 카메라 시험값 적용**은 500ms, 0.45초, 2프레임, 박스 높이 95%, YOLO 320px를 적용한다. 시작값은 기존 그대로이며 변경은 이번 프로세스에서 적용된다.

카메라 갱신 중단, 확정 목표 상실, 통신 및 fault, 긴급정지, 속도 한계와 후진 차단은 계속 적용한다. 손바닥은 재개, 주먹은 정지, 엄지는 목표 거리 조정에 사용한다. 대상 ID 자동 변경이나 승인 없는 주행 재개는 하지 않는다.

## 사용법과 검증 결과

기존 대시보드를 종료하고 [run_simulation.bat](../run_simulation.bat)로 다시 연다. 먼저 **손동작 추종 → 느린 카메라 시험값 적용**으로 시뮬레이션에서 검출·제스처 반응을 확인한다. 실물 시험은 C6의 정지 통신과 방향 확인을 마친 뒤 진행한다. 다른 모드를 해제하고 **실제 손동작 추종 연결 승인**을 누른 뒤, STOP 응답·목표 확정·제어 준비 [A]·손바닥 펼침 순서를 따른다. LLM은 기존 **자연어 제어** 탭에서 계획을 확인하고 별도로 1회 승인한다. [C6 실물 시험 절차](C6_HARDWARE_PREFLIGHT.md)

변경 파일은 [세션 판정](../python_controller/communication/session_sync.py), [UDP 송수신](../python_controller/communication/esp32_udp.py), [모터 시험](../python_controller/communication/motor_test.py), [거리 텔레메트리](../python_controller/execution/llm_telemetry.py), [거리 실행기](../python_controller/execution/motion_executor.py), [JSONL 기록](../python_controller/execution/run_log.py), [자연어 제어](../python_controller/llm/central_control.py), [중앙 관리자](../python_controller/dashboard_runtime.py), [제스처 상태 처리](../python_controller/control/state_machine.py), [대시보드](../python_controller/visualization/dashboard.py), [자연어 상태 UI](../python_controller/visualization/natural_control.py), [추종 설정 UI](../python_controller/visualization/follow_control.py), [통합 시험](../tests/test_session_integration.py), [탭 라벨 회귀](../tests/test_korean_diagnostics_ui.py) 및 이 문서다.

기존 115개와 신규 8개를 포함한 123개 테스트를 로컬 Wi-Fi 헤더를 제외한 임시 검증 복사본에서 통과했다. 원본 작업 폴더에서는 기존 출처 검사 1건이 사용자가 만든 로컬 `secrets.h` 존재 때문에 변경 전부터 실패했다. 원본 헤더와 테스트 조건을 유지했다. 재현 검증은 지연 응답, 부팅 변경, 제어권 충돌, 수동→LLM→손동작 전환, 다른 세션의 목표 도달, STOP 확인 및 재출발 금지를 포함한다.

실제 ESP32에서 신규 세션 획득 지연, 손동작별 실물 방향·정지 시간, 설정 변경 후 실제 영상 나이, 네트워크 다른 송신기 개입 시 물리 정지는 별도 시험이 필요하다.
