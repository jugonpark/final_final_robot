# D.I.G. Agent 스키마와 대화 처리

## 스키마 구현 현황

| 계층 | 구현된 범위 | 적용되는 제약 |
| --- | --- | --- |
| 이동 동작 | `Move`, `Rotate`, `Stop`의 Pydantic 구분 합집합 | 전·후·좌·우 이동은 블록당 5~50cm, 회전은 0° 초과~360°의 미리보기. 모든 이동 거리는 합계 100cm 이하이며 초안은 최대 4블록, 정지 블록은 마지막에만 허용한다. |
| 초안 | `DraftMission`, `MissionBlock`, `DraftOperation` | 같은 미션 ID 아래 편집할 때마다 버전이 증가한다. 추가·삽입·교체·삭제·순서 변경·전체 비우기가 SQLite에 반영된다. 마지막 블록을 지우면 활성 초안이 사라진다. 서버는 예상 버전을 비교하고 중복 요청 ID를 확인한다. |
| 화면·관제 조회 | `navigate`, `query_status`, `explain_blocked`, `query_vision`, `query_progress`, `explain_program`, `query_history`, `ask_docs` | 화면 이동과 제어 모드 전환은 별개다. 상태는 실제 런타임 스냅숏에서, 이력은 저장소에서, 매뉴얼 답변은 문서 검색 결과에서 가져온다. |
| 메뉴 설명 | `explain_menu` + `menu` | 미션 컨트롤, 작업 이력, 로봇 문서, 카메라·손동작, 수동 제어, 상태·진단, 설정 또는 전체 메뉴의 용도, 사용법과 화면의 제한을 설명한다. |
| 모드 전환 | `switch_mode`, `mode_then_plan` | 원문에 모드 이름과 전환 의도가 있어야 한다. 복합 요청은 기존 전환 절차를 통과한 뒤 이동 부분을 초안으로 처리한다. |
| 미션 의도 | `stage_motion`, `create_plan`, `create_sequence`, `modify_plan`, `edit_plan`, `edit_draft`, `show_draft`, `new_draft`, `reorder_draft`, `request_execution` | 편집 제안은 순번 또는 마지막 블록을 가리킨다. 서버가 원문에서 대상과 이동 수치를 확인하고 실제 블록 ID와 버전을 적용한다. 한 발화에서 여러 블록을 편집하는 요청은 되묻도록 안내한다. |
| 대화·중단 | `chat`, `clarify`, `identify`, `role_boundary`, `stop`, `cancel_plan` | 대화 의도에는 답변이나 제어 필드가 없다. 별도 응답 스키마에 답변 텍스트만 들어간다. 명시적인 긴급 정지는 로컬에서 먼저 처리한다. |
| 실행 승인 | LangGraph 검토 상태와 서버의 `ApprovalTicket` | 카드와 승인에 미션 ID·버전·세션이 연결된다. 운영자 승인으로 발급된 티켓은 5초 동안 한 번 사용할 수 있다. 초안 편집은 새 검토를 요구한다. 회전이 포함된 계획은 실행을 차단하며 실물 실행 승인은 Qt 관제에서만 가능하다. |

Pydantic 검증은 스키마에 없는 필드, 잘못된 타입, 숫자 문자열을 거부한다. 별도의 계획 검증은 순서와 전체 이동 거리를 확인한다. 텍스트를 그대로 파싱해 공급되는 제안도 같은 실행 제한을 적용받는다.

## 현재 LLM 동작

1. 서버는 긴급 정지·취소, 명시적인 정체성 질문, 정형화된 프로그램 소개와 일부 초안 조회·정렬을 먼저 처리한다. 이전 지시를 무시하거나 승인을 우회하라는 명시적 요청에는 기존 역할과 승인 절차를 안내한다.
2. **의도 분류**는 현재 메시지와 미실행 초안의 동작 목록으로 JSON 의도 객체 하나를 반환한다. Pydantic이 필드를 검사하며, 이동·편집 제안은 현재 사용자 원문과 대조해 방향, 수치, 단계와 버전을 확인한다.
3. **대화 생성**은 일반 대화와 확인 질문에서 별도로 NVIDIA 응답 스트림을 연다. 모델이 보내는 텍스트 조각은 문장 중간부터 웹의 SSE 연결로 전달된다. Qt는 현재까지 받은 텍스트를 화면 갱신 주기에 표시한다. 완료된 답변을 대화 기록에 저장한다. 최근 사용자 입력과 읽기 전용 답변을 합쳐 최대 10개 메시지를 문맥으로 사용한다. 장치 응답, 실행 영수증과 검색 문서 발췌는 대화 생성 문맥에서 제외한다. 최근 답변을 반복하면 한 번 새 답을 요청한다.
4. 상태 질문은 런타임 스냅숏을 조회하고, 기술·매뉴얼 질문은 로컬 SQLite FTS5 근거를 읽어 출처를 붙인다. 로컬 벡터 검색과 승인된 Git 문서의 클라우드 인용 선택은 별도 옵션이다. 알려진 문서 지시문 패턴을 발췌에서 걸러내고 클라우드 인용을 실제 원문에 대조한다. 문서 답변은 실행 경로와 분리된다.
5. LangGraph는 분류, 읽기 전용 답변, 문서 검색과 버전이 고정된 검토를 처리한다. Qt 운영자 승인과 실제 이동은 서버의 기존 실행 경로를 거친다. 실행 중 새 이동은 별도 미래 초안에 저장할 수 있다.

제품 역할은 D.I.G. 로봇 관제 에이전트이며 모델 이름은 Python의 `NVIDIA_MODEL` 설정에서 읽는다. 공식 NVIDIA 엔드포인트와 사용자 지정 엔드포인트는 서버 답변에서 구별한다. 모델 연결에 문제가 생겨도 웹 블록 직접 편집과 로컬 처리 경로는 이용할 수 있다.

## 대화 예시

| 사용자 입력 예시 | 처리 |
| --- | --- |
| “안녕”, “고마워” | `chat`으로 한 문장 답한다. 화면, 초안, 제어 상태에 영향을 주지 않는다. |
| “우리 프로그램 설명해 줘”, “그 내용을 예로 들어 줘” | 서버에서 프로그램을 소개하고, 후속 질문은 이전 설명을 포함한 읽기 전용 문맥으로 답한다. |
| “너는 어떤 모델이야?” | 서버가 D.I.G. 역할과 Python 설정의 공급자·모델을 답한다. |
| “각 메뉴에 대한 설명”, “카메라 · 손동작 메뉴 사용법” | 화면의 주요 항목과 사용 방법을 읽기 전용으로 설명한다. |
| “레이더 UNKNOWN은 무슨 뜻이야?”, “현재 레이더 상태는?” | 앞 질문은 근거 문서를 찾아 인용하고, 뒤 질문은 장치 스냅숏을 조회한다. 근거가 부족하면 확인 가능한 범위를 알려 준다. |
| “조금 앞으로”, “카메라로 제어할래” | `clarify`로 거리나 제어 모드 등 필요한 항목 하나를 묻고, 답을 받을 때까지 초안과 제어 모드를 유지한다. |
| “가장 작은 소수 두 개는?”, “그다음 두 개는?” | 일반 지식과 후속 질문으로 응답한다. |
| “오늘 부산 날씨 알려줘” | 일반 대화로 분류한다. 현재 날씨처럼 실시간 데이터가 필요한 질문에는 확인 가능한 범위를 설명한다. |
| “‘앞으로 5cm 이동해’라는 문장을 설명해 줘”, “‘멈춰’는 어떤 명령이야?” | 인용·설명으로 분류한다. 모델이 이동이나 정지로 해석하더라도 제어 상태는 유지한다. 독립 긴급 정지 버튼과 명시적인 정지 명령은 기존 경로를 따른다. |
