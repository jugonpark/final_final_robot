# UX/UI 상세 명세 — D.I.G. Blue

## 0. 사용자 목표

로봇을 **대화로 움직이는 AI 명령**과 **손동작/카메라 제어**가 앱의 두 가지 중심 기능. 고장 원인 분석, 바퀴 실측, 통신 설정은 개발 시 중요하지만 일반 화면에서는 보조적이다.

## 1. 디자인 시스템

- 컬러: APP `#071324`, SIDEBAR `#0A1A30`, SURFACE `#10253E`, PRIMARY `#2379F5`, ACCENT `#40CBFF`, TEXT `#EAF3FF`, MUTED `#97B1CA`.
- 상태 예외: 정상 `#25BC91`, 주의 `#F2B64C`, 위험/비상정지 `#E95462`.
- 글꼴: Windows `맑은 고딕` 기본 (프로젝트 외부 폰트 패키징 금지). 다크 배경에서 작은 글자 대비 유지.
- 레이아웃: 사이드바 248px, 헤더 78px, 콘텐츠 가변폭, 카드 모서리 16px, 버튼 11px.
- 버튼: Large 52px, Medium 44px, Small 34px. 비활성은 저채도 표시/클릭 불가. 로딩은 버튼 중복 입력 차단 및 텍스트 피드백.
- 카드, 입력, 상태바는 `qt/dig_blue.qss` 참조. SVG 아이콘은 `QIcon`으로 불러온다. 영문 프로토콜 ID는 진단에서만 사용.

## 2. 공통 영역

**사이드바 5개:** AI 대화 제어 / 카메라·손동작 / 수동 제어 / 상태·진단 / 설정. 앱 시작 기본 **AI 대화**. 선택된 시각적 페이지와 실제 모터 제어권 `active_control_mode`를 엄격히 구별.

**상단 헤더:** ESP32 연결 상태, 레이더 `CLEAR/EVADE/UNKNOWN`+blocked, 카메라 상태, E-STOP. 숫자를 임의 생성하지 않으며 실제 데이터가 없으면 `미수신/미확인`.

**위험 알림:** 레이더 `EVADE` 또는 `UNKNOWN`, 미확인 STOP, 재허용 대기 등은 실행 불가 사유로 명확히 표시. CLEAR라도 재허용·STOP 확인 전이면 구동 가능 배지를 표시하지 않는다.

## 3. AI 대화 제어 — 메인

구조: **왼쪽 대화 60~65%, 오른쪽 실행 계획/정지 상태 35~40%**. 자연어 한 번 입력 → 계획 생성 상태 → 검증된 `ValidatedPlan.actions` 시각화 → 기존 승인·실행 버튼 → 실행 피드백. ChatGPT 같은 UI이지만 **대화 기억/다중 턴 LLM 문맥은 현재 미구현**; 한 건 요청과 현재 계획만 카드로 표현. 마이크 아이콘/버튼은 만들지 않는다.

- [시안] 사용자 메시지 버블 / 시스템 안내 버블 / 단계별 실행 카드 / 제어 차단 사유.
- [실제 연결] `NaturalControlPanel.command`, `.plan_button`, `.preview`, `.execute_button`, `.status`, `.gate`, `.telemetry`, `.session_status`, `.log`.
- 모델 출력만으로 실행하지 않음. `NaturalControl.phase` + 기존 `can_prepare`/`execute_button.setEnabled` 게이트 재사용.
- `Rotate` 포함: 카드에 360° 회전 표시하되 **실제 실행 불가(각도 제어 미검증)**. 화면에 `실행` 버튼을 시각적으로만 활성화해서는 안 된다.
- 레이더 차단 또는 STOP 미확인 시 계획 생성을 막을 필요는 없으나 **실행 버튼은 기존 로직대로 비활성**.

## 4. 카메라·손동작

큰 실시간 카메라, 오른쪽 인식 상태·최종 적용 명령·제스처 가이드. 세그먼트로 **직접 손동작**과 **사람 추종** 모드를 분리. 기존 **하나의** `CameraView` 인스턴스를 재사용한다.

**직접 제어 기본 매핑 (`hand_drive.DEFAULT_MAPPING`)**: Open Palm→전진, Victory→후진, Thumb Up→좌측, Thumb Down→우측, Closed Fist→정지(고정). UI에서 매핑 변경했으면 실제 설정을 기준으로 렌더링.

**사람 추종 기본 매핑 (`config/default.json`)**: Open Palm→재개, Closed Fist→일시 정지, Thumb Up→목표 간격 감소, Thumb Down→목표 간격 증가. 이 화면에서 Open Palm에 '전진'이라고 설명하면 안 됨.

**인식 데이터 구별**: 최초 인식 결과/신뢰도, 지속 확인된 제스처, 실제 적용 명령, 실패/보류 이유. 모델 준비 중 원본 영상 표시는 인식 성공이 아님.

## 5. 수동 제어

버튼 6개: 전진/후진/좌측/우측/좌회전/우회전. 중앙 방향 패드 형태. **버튼 유지 시 이동**과 **떼면 정지** (`pressed/released`) 보존. 페이지 전환 또는 창 비활성화 시 반드시 `end_motor_hold()` 호출. 별도 `M1/M2/M3` 바퀴 시험은 진단 내 기존 위치를 보존.

## 6. 상태·진단

보여줄 것: 최신 텔레메트리의 목표/실측 RPM, 엔코더, PWM; 연결 검증·레이더 수신 경과·카메라 지연·Fault·STOP 확인·기록/보고서·엔코더 복구·바퀴 시험. 센서가 없는 배터리/IMU/지도는 추가하지 않음.

## 7. 설정

ESP32 IPv4·레이더 Pi IPv4·제스처 매핑·카메라·추종 설정·기존 정책 변경 UI를 재배치. 입력값 저장/편집 가능 시점은 기존 UI 로직을 그대로 유지. UI 탭 이동이 실제 연결, 권한 또는 레이더 설정을 임의로 변경하지 않게 한다.

## 8. 최소 화면 대응

기준 1600×980. 실사용 1320×920, 작은 창 940×680에서 가로 콘텐츠가 겹치지 않도록 `QScrollArea`와 가변 `QSplitter`. 헤더 E-STOP은 절대 스크롤 밖으로 밀리지 않아야 하며 `Space/E` 단축키를 유지.
